## Covergroup: `axi4l_cg`

Sampled inside `axi4l_coverage::write()` — once per write transaction and once per read transaction, driven by `txn_sel` bit field from the sequence item.

---

### Coverpoint 1: `cp_operation_type`

**Variable:** `{is_write, is_read}` (2-bit concatenation)
**Goal:** Confirm both write-only and read-only transaction types are exercised.

| Bin Name | Value | Description | Sequences That Hit It | Status |
|---|---|---|---|---|
| `bin_op_write` | `2'b10` | Write transaction | `axi4l_write_seq`, `axi4l_normal_rw_seq`, `axi4l_ro_test_seq`, `axi4l_wo_test_seq`, `axi4l_decerr_seq`, `axi4l_unaligned_seq`, `axi4l_concurrent_seq`, `axi4l_fully_rand` | ✅ |
| `bin_op_read` | `2'b01` | Read transaction | `axi4l_read_seq`, `axi4l_normal_rw_seq`, `axi4l_ro_test_seq`, `axi4l_wo_test_seq`, `axi4l_decerr_seq`, `axi4l_unaligned_seq`, `axi4l_concurrent_seq`, `axi4l_fully_rand` | ✅ |

**Note:** `2'b00` (no transaction) and `2'b11` (concurrent) are not binned — concurrent transactions are sampled as two separate calls (one write sample, one read sample), so `cp_operation_type` sees them as individual write and read events.

---

### Coverpoint 2: `cp_address_region`

**Variable:** `addr` (32-bit — set to `AWADDR` for writes, `ARADDR` for reads)
**Goal:** Ensure all register regions defined in spec Section 10 are accessed.

| Bin Name | Address Range | Access Type per Spec | Sequences That Hit It | Status |
|---|---|---|---|---|
| `bin_addr_normal_rw` | `0x00–0x24`, `0x3C` | Read/Write (normal + reserved) | `axi4l_normal_rw_seq`, `axi4l_fully_rand` | ✅ |
| `bin_addr_read_only` | `0x28`, `0x2C`, `0x30` | Read-Only (status registers) | `axi4l_ro_test_seq`, `axi4l_fully_rand` | ✅ |
| `bin_addr_write_only` | `0x34`, `0x38` | Write-Only (command registers) | `axi4l_wo_test_seq`, `axi4l_fully_rand` | ✅ |
| `bin_addr_out_of_bounds` | `0x40–0xFFFFFFFF` | Invalid → DECERR | `axi4l_decerr_seq`, `axi4l_fully_rand` | ✅ |

**Gap:** Unaligned addresses (`ADDR[1:0] != 2'b00`) are not a separate bin in `cp_address_region`. They are covered behaviorally via `axi4l_unaligned_seq` hitting the scoreboard SLVERR check, but not tracked as a distinct functional coverage bin. Consider adding `bin_addr_unaligned` in a future revision.

---

### Coverpoint 3: `cp_write_strobe`

**Variable:** `wstrb` (4-bit)
**Guard:** `iff (is_write == 1)` — only sampled on write transactions
**Goal:** Verify all 16 WSTRB byte-enable combinations per spec Section 17.

| Bin Name | Values | Description | Status |
|---|---|---|---|
| `bin_wstrb_combinations[]` | `4'b0000` to `4'b1111` (auto-expanded, 16 bins) | All byte-enable combinations — full word, partial byte, no-op | ✅ (via `axi4l_fully_rand` randomizing WSTRB) |

**Specific meaningful combinations per spec:**

| WSTRB | Bytes Written | Meaningful Scenario |
|---|---|---|
| `4'b0001` | Bits [7:0] | Byte 0 only |
| `4'b0010` | Bits [15:8] | Byte 1 only |
| `4'b0100` | Bits [23:16] | Byte 2 only |
| `4'b1000` | Bits [31:24] | Byte 3 only |
| `4'b0011` | Bits [15:0] | Lower halfword |
| `4'b1100` | Bits [31:16] | Upper halfword |
| `4'b1111` | Bits [31:0] | Full 32-bit word write |
| `4'b0000` | None | No-op write |

---

### Coverpoint 4: `cp_axi_response`

**Variable:** `resp` (2-bit — set to `t.RESP` from seq item, captured from DUT)
**Goal:** Confirm all AXI response encodings defined in spec Section 9 are generated by the DUT.

| Bin Name | Value | AXI Response | Condition per Spec (Sec 20) | Sequences That Hit It | Status |
|---|---|---|---|---|---|
| `bin_resp_okay` | `2'b00` | OKAY | Valid aligned write/read to correct region | `axi4l_normal_rw_seq`, `axi4l_write_seq`, `axi4l_read_seq` | ✅ |
| `bin_resp_slverr` | `2'b10` | SLVERR | Unaligned access OR write to RO OR read from WO | `axi4l_ro_test_seq`, `axi4l_wo_test_seq`, `axi4l_unaligned_seq` | ✅ |
| `bin_resp_decerr` | `2'b11` | DECERR | Address out of range (> 0x3F) | `axi4l_decerr_seq` | ✅ |

**Note:** `EXOKAY (2'b01)` is not binned — not generated by this slave (no exclusive access support per design).

### Cross Coverage 1: `cross_op_x_address`

**Cross:** `cp_operation_type` × `cp_address_region`
**Goal:** Confirm both reads and writes hit every address region — not just that each was accessed independently.

| Cross Bin | Operation | Address Region | Key Scenario | Status |
|---|---|---|---|---|
| `bin_op_write` × `bin_addr_normal_rw` | Write | 0x00–0x24, 0x3C | Normal write → OKAY | ✅ |
| `bin_op_write` × `bin_addr_read_only` | Write | 0x28–0x30 | Write to RO → SLVERR | ✅ |
| `bin_op_write` × `bin_addr_write_only` | Write | 0x34–0x38 | Write to WO → OKAY | ✅ |
| `bin_op_write` × `bin_addr_out_of_bounds` | Write | > 0x3F | Write OOB → DECERR | ✅ |
| `bin_op_read` × `bin_addr_normal_rw` | Read | 0x00–0x24, 0x3C | Normal read → OKAY | ✅ |
| `bin_op_read` × `bin_addr_read_only` | Read | 0x28–0x30 | Read from RO → OKAY | ✅ |
| `bin_op_read` × `bin_addr_write_only` | Read | 0x34–0x38 | Read from WO → SLVERR | ✅ |
| `bin_op_read` × `bin_addr_out_of_bounds` | Read | > 0x3F | Read OOB → DECERR | ✅ |

## Coverage Exclusions

| Signal / Block | Reason for Exclusion |
|---|---|
| `EXOKAY (2'b01)` response | Not generated by this slave — no exclusive access support |
| `AWPROT`, `ARPROT` | Protection attributes not decoded by DUT — tied off in testbench |
| `4'b0000` WSTRB | No-op write — DUT accepts but no memory update; included in bin but behavioral impact is zero |
